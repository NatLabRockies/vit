# FloatingFeedback Fix and Phase 7B Extraction Complete
**Date:** 2026-03-24
**Status:** completed
**Scope:** KGen DLL persistence workaround generalization, Phase 7B extraction campaign

## The Problem

FloatingFeedback (Controllers.f90:96) captured 0 state files while all 6 DISCON.F90 functions extracted successfully (20 cases each). The DLL SAVE persistence workaround from the previous fix was DISCON.F90-specific — it anchored the KGen DEALLOCATE sed on `CALL ReadAvrSWAP`, a line that only exists in DISCON.F90.

## Root Cause

The build wrapper's DEALLOCATE patch:
```bash
sed -i '/CALL ReadAvrSWAP/i\    IF (NINT(avrSWAP(1)) == 0 .AND. ALLOCATED(kgen_isstop)) THEN
    DEALLOCATE(...)
END IF' "$f90"
```

This sed matched nothing in Controllers.f90 (no `CALL ReadAvrSWAP` there). The KGen SAVE arrays (`kgen_isstop`, `kgen_invoke`, `kgen_islast`, etc.) persisted from the profiling phase, preventing fresh state capture. The invocation counter was stale and the stop flags were already set.

## Fix

Changed the sed anchor from `CALL ReadAvrSWAP` to `IF (.NOT. ALLOCATED(kgen_isstop))` — the KGen init check that exists in ALL KGen-instrumented files. This is generated by KGen's code generator for every extraction, regardless of which source file contains the call site.

```python
# Before (DISCON.F90-only):
"sed -i '/CALL ReadAvrSWAP/i\\    IF (NINT(avrSWAP(1)) == 0 ..."

# After (all instrumented files):
"sed -i '/IF (.NOT. ALLOCATED(kgen_isstop))/i\\        IF (NINT(avrSWAP(1)) == 0 ..."
```

The `NINT(avrSWAP(1)) == 0` condition (iStatus=0) works in Controllers.f90 because PitchControl receives `avrSWAP(*)` as a parameter. The `AlreadyInitialized = 0` reset remains anchored on `CALL ReadAvrSWAP` — it's DISCON-specific and correctly no-ops on other files.
