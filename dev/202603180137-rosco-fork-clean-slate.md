# ROSCO Fork — Clean Slate with Tracked VIT Files
**Date:** 2026-03-18
**Status:** completed
**Scope:** ROSCO repo setup, git workflow

## What Was Done

Forked NREL/ROSCO to `kevinmenear/ROSCO` and re-cloned fresh to replace the previous untracked ROSCO directory. VIT-specific files are now committed to the fork so changes are tracked.

### Why

The original ROSCO was cloned directly from NREL/ROSCO. VIT work products (translations, vit.yaml, kernel fixtures, TRANSLATION_TIPS.md) were untracked files sitting in the working directory. This made it impossible to track changes to translations over time, share the state with collaborators, or roll back to a known-good state.

With the fork, all VIT files are committed and pushed. The ROSCO repo becomes the single source of truth for translations, config, and golden fixtures — consistent with the PROJECT_PLAN.md decision that translations are ROSCO-specific artifacts that belong with the target codebase.

### Process

1. Backed up VIT-specific files to `/tmp/rosco-vit-backup/`:
   - `vit.yaml` — pipeline configuration
   - `translations/Functions/` — 4 C++ translations with metadata headers (saturate, wrap_180, wrap_360, interp1d)
   - `TRANSLATION_TIPS.md` — living document for translation lessons
   - `kernel/saturate/`, `kernel/wrap_180/` — golden KGen extraction fixtures (~48 MB)

2. Removed old ROSCO directory

3. Cloned fresh from `git@github.com:kevinmenear/ROSCO.git`

4. Restored VIT files from backup

5. Added VIT-specific entries to `.gitignore`:
   - `kernel/**/*.o`, `kernel/**/*.exe`, `kernel/**/*.csv` — build artifacts (regenerated by `vit verify`)
   - `kernel/**/*_cpp.cpp`, `kernel/**/*_impl.hpp` — generated C++ wrappers (regenerated by `vit verify`)
   - `state/`, `model.ini`, `include.ini`, `kgen.log` — extraction intermediates
   - `baseline_output.txt`, `integrated_output.txt` — simulation comparison files

6. Committed all VIT files as first commit on the fork (`e8010f0`)

### What's Tracked vs Ignored

**Tracked** (committed to the fork):
- `vit.yaml` — VIT pipeline configuration
- `TRANSLATION_TIPS.md` — translation lessons
- `translations/Functions/*.cpp` — C++ translations with metadata headers
- `kernel/<function>/*.f90` — KGen-generated Fortran sources (part of the golden fixture)
- `kernel/<function>/<function>.0.0.*` — captured runtime state data (the actual golden data)
- `kernel/<function>/kgen_statefile.lst` — state file manifest
- `.gitignore` — updated with VIT entries

**Ignored** (regenerated by VIT commands):
- `kernel/**/*.o` — compiled objects
- `kernel/**/*.exe` — kernel executable
- `kernel/**/*.csv` — field verification logs
- `kernel/**/*_cpp.cpp`, `kernel/**/*_impl.hpp` — C++ wrapper files generated by `vit verify`
- `state/`, `model.ini`, `include.ini`, `kgen.log` — extraction intermediates
- `baseline_output.txt`, `integrated_output.txt` — simulation output comparisons

### Docker Container

The Docker container (`vit-dev`) mounts `vit_translation/` as `/workspace/`. Since the ROSCO directory is at the same path, the container sees the new clone automatically. Verified that the container can access `vit.yaml`, `translations/Functions/`, and all kernel fixtures.

The container's editable pip install of ROSCO (`pip install -e /workspace/ROSCO`) may need to be re-run since the `.egg-info` directory was lost with the re-clone. This will be needed before running simulations but not for VIT commands that don't import ROSCO Python code.
