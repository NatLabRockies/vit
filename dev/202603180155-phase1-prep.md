## CPfunction Is Dead Code

While reviewing Phase 1 readiness, we tested `vit translate CPfunction` and `vit find CPfunction`. The parser and scaffold generation work correctly (`CP(4)` is parsed as a fixed-size array, `build_c_params()` produces `double* CP` with no size param). However, a codebase-wide search revealed that `CPfunction` is defined in Functions.f90 but **never called anywhere in ROSCO** — not in Controllers, ControllerBlocks, or any other module.

This means KGen extraction cannot capture runtime state for it (no call site to instrument, simulation never invokes it). Without runtime state, verification is impossible through the standard VIT pipeline.

Decision: skip CPfunction entirely. If a call site is added in a future ROSCO version, it can be picked up then.
