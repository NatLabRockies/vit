# CheckValuesAreUniqueMonotonicIncreasing + test-validate Enhancement
**Date:** 2026-04-27
**Status:** completed
**Scope:** 15th AirfoilInfo function, VIT test-validate infrastructure enhancement

## What Was Done

### VIT Enhancement: FUNCTION Return Types + Assumed-Shape Arrays

`vit test-validate` previously only handled SUBROUTINEs with scalar/derived-type arguments. CheckValuesAreUniqueMonotonicIncreasing hit two gaps:

1. **FUNCTION return types** — the bridge always generated `CALL func(...)`, but Fortran FUNCTIONs need `result = func(...)`. Fixed by detecting `sig.is_function` and adding a `vit_result` output parameter to the bridge signature. For LOGICAL returns, the conversion uses `LOGICAL(..., C_BOOL)`.

2. **Assumed-shape array arguments** — `secondVals(:)` was treated as a scalar. Fixed by detecting `arg.is_array and arg.is_assumed_shape` and generating: (a) assumed-size declaration `secondVals(*)`, (b) size parameter `INTEGER(C_INT), VALUE :: n_secondVals`, (c) explicit section in the call `secondVals(1:n_secondVals)`. The explicit section converts assumed-size to a form Fortran can pass to assumed-shape parameters.

Both patterns already existed in `interface_gen.py` (the integration path). The enhancement mirrors that logic in `test_validate.py`'s `generate_fortran_bridge()`.

8 new unit tests added to `test_test_validate.py` covering FUNCTION detection, LOGICAL C_BOOL conversion, assumed-shape size parameters, and non-regression for SUBROUTINE bridges.

### CheckValuesAreUniqueMonotonicIncreasing (15th Function)

19-line PRIVATE FUNCTION — validates that a real array is strictly monotonically increasing and unique (no duplicates within EqualRealNos tolerance). Called by AFI_Init and ReadAFfile to validate Reynolds number / UserProp table ordering.

**Translation:** Trivial — loop from index 1 to n-1, check `EqualRealNos(a[i], a[i-1]) || a[i] < a[i-1]`.

**Verification:** 11/11 dual-call test-validate (C++ ≡ Fortran on every branch):
1. Happy path — strictly increasing array
2. Single element — loop skipped, returns true
3. Two elements increasing/equal/decreasing
4. Equal pair in middle
5. Decreasing pair in middle
6. Failure at last pair (tests early exit)
7. Near-equal within EqualRealNos tolerance
8. Large values
9. Negative values

**No standalone integration** — this is a PRIVATE helper. It will be included as a static function inside the AFI_Init translation when that function is translated. The test-validate verification proves the C++ matches Fortran; the production integration happens later.

## Generated Bridge (Demonstrates Both Enhancements)

```fortran
SUBROUTINE checkvaluesareuniquemonotonicincreasing_f90(secondVals, n_secondVals, vit_result) &
    BIND(C, NAME='checkvaluesareuniquemonotonicincreasing_f90')
    USE ISO_C_BINDING
    USE AirfoilInfo
    IMPLICIT NONE
    REAL(C_DOUBLE), INTENT(IN) :: secondVals(*)        ! assumed-shape → assumed-size
    INTEGER(C_INT), VALUE, INTENT(IN) :: n_secondVals   ! size parameter
    LOGICAL(C_BOOL), INTENT(OUT) :: vit_result          ! FUNCTION return as output
    vit_result = LOGICAL(CheckValuesAreUniqueMonotonicIncreasing(secondVals(1:n_secondVals)), C_BOOL)
END SUBROUTINE
```

This bridge was auto-generated by the enhanced `vit test-validate` — no manual writing needed.
