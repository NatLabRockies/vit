# DBEMT_ReInit Translation + KGen Extraction Failure
**Date:** 2026-05-01
**Status:** completed
**Scope:** DBEMT Phase D (2/3), KGen instrumentation bug

## Summary

DBEMT_ReInit (45 lines, DBEMT.f90:404-448) is an initialization reset function that zeros continuous states, resets OtherState flags/scalars, copies zeroed states into 4 history slots, and sets a MiscVar warning flag. Translated, verified via custom Fortran test harness (4/4 PASS), integrated (17/17 baselines PASS).

## KGen Extraction Failure

Coverage data confirmed 6 test cases exercise DBEMT_ReInit (most coverage from `ad_BAR_CombinedCases` — 7 hits total). KGen extraction was attempted twice and failed both times with identical errors:

```
Error: Symbol 'x' at (1) has no IMPLICIT type
Error: Symbol 'm' at (1) has no IMPLICIT type
Error: Expecting END MODULE statement at (1)
Error: Symbol 'dbemt_reinit' at (1) has no IMPLICIT type
```

**Root cause:** KGen's source instrumentation placed state-capture code (referencing local variables `x` and `m`) outside the subroutine scope — likely at the module level where those variables aren't declared. The instrumented production build fails to compile, so no state data is captured.

**Why other DBEMT functions extracted successfully:** Functions like UpdateStates, CalcOutput, and the time integrators all extracted without this issue. The difference may be related to ReInit's simpler signature (no ErrStat/ErrMsg outputs), its position in the source file relative to other instrumented functions, or its callee (`DBEMT_CopyElementContinuousStateType` is in DBEMT_Types.f90, not DBEMT.f90).

**Workaround:** Custom Fortran test harness (same approach as InitStates_AllNodes). This is the fourth verification method used in the DBEMT translation.

## Translation Details

### CopyElementContinuousStateType Handling

The Fortran calls a Registry-generated copy routine:
```fortran
call DBEMT_CopyElementContinuousStateType(x%element(i,j), OtherState%xdot(n)%element(i,j), MESH_UPDATECOPY, ErrStat2, ErrMsg2)
```

This routine is trivial — copies two 2-element real arrays (`vind`, `vind_1`), ignores `CtrlCode`. In C++, this becomes direct struct field assignment, the same pattern used by RK4, AB4, and ABM4 translations. This is the idiomatic C++ equivalent, not inlining to work around a problem — the Registry routine exists because Fortran's type system requires explicit copy subroutines for derived types.

The routine is only called from ReInit within DBEMT.f90 (and from DBEMT_Types.f90 internal Registry plumbing). No other C++ translation calls it.

### MiscVarType View Struct

DBEMT_MiscVarType has a single field: `LOGICAL :: FirstWarn_tau1`. VIT auto-detected this as C-compatible (no ALLOCATABLEs) and generated `dbemt_miscvartype_t` with `int32_t FirstWarn_tau1`. The struct is passed directly via `C_LOC(m)` — no view populator needed.

### Test Harness Design

4 test cases covering all branches:

| Test | DBEMT_Mod | n allocated | Key assertion |
|------|-----------|-------------|---------------|
| tauConst_alloc_5x3 | 1 | yes | tau1 = tau1_const, n = -1, xdot copied |
| tauVaries_alloc_3x2 | 2 | yes | tau1 = 0.0, n = -1 |
| cont_tauConst_2x2 | 3 | yes | tau1 = tau1_const |
| n_not_alloc_3x2 | 1 | no | n block skipped |

Setup populates x%element with non-zero values, sets areStatesInitialized to .TRUE., sets OtherState%n to 5, sets m%FirstWarn_tau1 to .FALSE. — all inverted from what ReInit should produce, so every field is verified as changed.

### Build Issue: vit_nwtc.cpp Undefined Symbol

The test Makefile links against `libaerodynlib.a` which has an undefined reference to `EqualRealNos` (from the integrated ValidateInitInp translation). The C++ `EqualRealNos` is declared in `vit_nwtc.h` and implemented in `vit_nwtc.cpp`, but the symbol isn't exported from the .a archive — it's only resolved in the full CMake link chain. Fixed by compiling `vit_nwtc.cpp` directly into the test binary.

### Build Issue: Local vit_types.h Conflict

The `translations/DBEMT/vit_types.h` only contains `dbemt_initinputtype_view_t` (regenerated by `vit test-validate` for ValidateInitInp). The ReInit translation needs all DBEMT view types. The Makefile copies the production `vit_types.h` (from `modules/aerodyn/src/`) over the local one before compiling, with backup/restore.
