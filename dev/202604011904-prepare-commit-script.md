# prepare_commit.sh: Standardizing the Pre-Commit Workflow

**Date:** 2026-04-01
**Status:** completed
**Scope:** New script to bridge the gap between integration testing and git commit

## The Problem

On main, ROSCO has a dual state:
- `.f90` files: clean Fortran (no integration wrappers)
- `src/*.cpp` files: full integration content (not stubs)

Neither `reset_to_clean.sh` nor `integrate_all.sh` produces this state:
- `reset_to_clean.sh`: .f90 clean, .cpp stubs (wrong for commit)
- `integrate_all.sh`: .f90 wrappers (wrong for commit), .cpp integration content

After a test cycle (reset → baseline → integrate → compare), committing required manual git gymnastics: restoring .f90 files, keeping .cpp content, discarding DISCON date artifacts, removing transient arrays, etc. This was error-prone and inconsistent.

## The Solution

`scripts/prepare_commit.sh` runs after the test cycle and produces the correct commit state:

1. **Restore .f90 files** to clean Fortran (same commits as reset_to_clean.sh)
2. **Restore src/*.cpp files** to committed state via `git checkout` (integration regenerates them with slightly different output due to VIT code changes — the committed versions are canonical)
3. **Restore DISCON_*.IN files** to committed dates
4. **Remove transient artifacts** (baseline_arrays/, integrated_arrays/, core dumps, header copies)
5. **Verify** clean state (0 wrapper calls in .f90, 0 stub .cpp files)

## Bug Found During Stress Testing

The DISCON_*.IN restore had a glob bug: `git checkout -- Examples/DISCON_*.IN` expanded to include both tracked AND untracked DISCON files (like DISCON_ipc_awc.IN, DISCON_su_sd_tra.IN — generated by vit_sim.py scenarios but not tracked). Git fails on the first untracked file and aborts the entire command. The `|| true` suppressed the error, so the tracked files were never restored.

**Fix:** Use `git ls-files` to filter to only tracked files:
```bash
tracked_discon=$(git ls-files 'Examples/DISCON_*.IN')
if [ -n "$tracked_discon" ]; then
    echo "$tracked_discon" | xargs git checkout --
fi
```

## Why src/*.cpp Needs git checkout (Not Integration Content)

`vit integrate --apply` regenerates src/*.cpp files each time, but the output isn't perfectly idempotent — minor differences in VIT boilerplate (e.g., extra `#include` lines) cause all 41 .cpp files to show as modified even when their translations haven't changed. Restoring from git ensures only genuinely changed files appear in `git status`.

For NEW functions (not yet committed), the workflow is:
1. Run `prepare_commit.sh` (restores everything)
2. Run `vit integrate NewFunction --apply` (generates the new src/*.cpp)
3. Restore the .f90 wrapper: `git checkout -- rosco/controller/src/TheSourceFile.f90`
4. Now only the new .cpp and changed tracked files appear

## Standardized Commit Workflow

```
reset_to_clean.sh → build → baseline capture
→ integrate_all.sh → build → sim comparison
→ prepare_commit.sh → git add + git commit
```
